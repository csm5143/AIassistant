## 如何复现基础验证

```bash
cd backend
mvn test
cd ../user-frontend
npm ci
npm run build
node --test tests/*.cjs
cd ../deployment/pdf-parser
python -m unittest test_text_cleanup
cd ../..
python deployment/init-env.py
docker compose --env-file .env.docker up --build -d
python scripts/smoke-deployment.py
# 在隔离测试部署中验证重启：显式指定该测试部署的项目名
python scripts/smoke-deployment.py --restart --project aiassistant-stack
# 开启 parser profile 后，再验证合成 PDF
python scripts/smoke-parser.py
```

冒烟检查包含前端资源、数据库健康、鉴权、随机管理员登录、会话创建、记忆接口、本地计算的 SSE 返回、任务记录与测试会话清理。它仅验证相应部署链路，**不代表真实模型回答质量或 OCR 准确率**。建议只对隔离的测试部署运行，避免给实际使用环境增加测试会话。

首次容器验证修复了管理员初始化选错数据库连接、Windows 专属 Python 依赖无法在 Linux 安装、构建上下文带入本机产物、对话图片缺少持久化目录等问题。完成修复后才记录上述通过结果。

## 已有性能记录（历史摘要）

### 简单问答与上下文成本

2026-10-02 的同组 10 题真实 API 对照包含 40 轮合成历史。输入 token 从 **17,575 降至 4,384（减少 75.1%）**，回答模型请求从 9 次降至 7 次，两轮检查均为 10/10。新版本地日期与数值计算不调用模型，独立短问题缩减上下文，追问仍保留必要历史。

新旧评测原始日志和旧版本快照未随仓库公开。因此该数字是历史验收摘要，不能仅运行当前代码就复现新旧对照；也不能外推为所有场景的平均节省或响应速度提升。部分问题延迟曾增加，失败复测的模型用量不应从成本统计中删除。

### 完整表格统计

2026-10-03 使用 [UCI Wine Quality](https://archive.ics.uci.edu/dataset/186/wine+quality) 原始红酒 CSV（分号分隔、1,599 行、12 列）进行独立 `csv` + `Decimal` 核对，检查条件筛选、行编号、分组、合计及原始列定位。

独立结果：`quality >= 7 && alcohol >= 11` 为 154 行；quality 3–8 的组计数分别为 10、53、681、638、199、18。alcohol 列合计 16666.35 仅用于十进制精度核对，不解释为科学结论。数据集及原始评测文件不随仓库上传。

历史整套 28 项场景回归在当时指定修复阶段达到 28/28；后续升级采用定向变式与小批次验证，**并未在最终发布包上重新跑整套收费评测**，因此不将该通过率当作当前版本全场景正确率。

## 后续评测建议

分别建立代码、日常聊天、简单任务、常识咨询、资料搜查、引用核验、统计、记忆隔离与任务恢复场景。每批记录：

- 源码提交、模型与参数、资料来源及哈希、测试输入和判分标准。
- 正确性、引用是否支持结论、行定位与权限隔离。
- 首字时间、总耗时、模型请求、输入/输出 token、嵌入 token、联网请求。
- 失败和超时未知状态，不能把失败调用从用量中去掉。
- 需要人工复核的判断，以及尚未覆盖的使用边界。

公开版评测看板不附带本地历史结果文件；暂无记录时显示空状态。部署者可生成自己的脱敏汇总，详细消息、账号和原始材料应留在私有环境。
